本次只处理一个完整用例。将描述整理为有序业务目标块和验证意图，只返回符合提供的 schema 的 JSON 对象，不附加解释或 Markdown，不拆分为多个用例。

保留用户原意，不新增或删除业务操作、数据、验证；原样保留文本、应用名、次数、方向、时长、间隔。不确定的信息不能猜测。
每个 step 表达一个业务目标或一轮完整流程。每条 instruction 只包含 id、text、kind，完整保留用户指定的应用名称、输入原文、次数、方向、时长、间隔等信息在 text 中，尤其保留引号内的空格、换行和符号。不寻找或单独提取参数，不生成参数表，不选择工具，不猜坐标和控件入口；实际调用方式和参数由后续探索阶段结合页面决定。
一条 instruction 也是语义要求，不等于一个手机动作。“返回应用首页”保留为一个要求，不推测要按几次返回；单一目标不人为拆成点击/输入/返回清单。仅为保留用户明确的多个环节或中间验证位置设置多个指令。
整组流程的重复次数只写入 repeat；goal 和 instructions 描述一轮，不展开多个块。连续滑动次数和等待时长属于一轮内的操作要求，保留在 text 中，不写入 step.repeat。
验证按语义提取，不按“确认”等关键词机械分类；点击确认按钮是操作。验证预期不判断正确性，不混入操作。
每条验证必须有 anchor，包含 step_id、instruction_id 和 position；整块边界 instruction_id 填 null，块内边界填对应指令 ID。position 是 before/after。scope=each_iteration 表示循环内该位置，outside_repeat 表示整块循环外，后者不关联内部指令。
重复的一轮包含中间验证时，保留单个 step，通过内部指令锚定验证。不得把整轮拆成各自重复的步骤。
验证要求导航时，导航是操作，预期检查是验证。没有验证则 verifications=[]。
step、instruction、verification 的 ID 分别唯一。验证锚点引用本次输出中实际存在的 step 和 instruction，按原文的操作与验证顺序绑定。未明确给出的操作数据不补写，含糊的操作描述按原意保留，不推测页面路径，不增加用于解释缺失信息的额外字段。
只负责整理描述，不操作手机，不生成脚本。没有操作则 steps=[]，不补操作。
所有声明字段都要返回，不添加 schema 以外的字段；空列表填 []，可空字段填 null，repeat 无重复时填 1。schema_version 和 source_revision 由程序填写，不在输出中生成。

输入：
{state_json}

若输入为确认稿：编号目标标题是摘要，后续操作行是具体指令，不把标题与指令重复计为两次操作。“每轮验证”在循环内，“循环外验证”在整组重复流程之外。

指令 kind 按语义选择：启动应用 app_launch、停止应用 app_stop、返回系统桌面 system_home、打开系统多任务 multitask，其余 ui。启动或停止应用时，将用户指定的应用名称保留在 text 中，不另建应用名称字段。明确测试点击图标本身属于 ui，不替换为应用启动。kind 不包含插件工具名。
返回应用首页不是返回系统桌面，前者必须是 ui；返回上一页、关闭面板或退出当前页面也不等于停止应用，不分类为 app_stop。
